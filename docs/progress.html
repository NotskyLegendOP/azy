Requirements that will not be built as written
Permanent decisions, not backlog: each one would need a technique this project rules out (injection, hooking, patching, constant screen capture). The closest possible treatment is named instead.
§16 Selected/unselected clip styling, playhead stylingClips and the playhead are painted by Premiere inside one window. Recolouring them means hooking its renderer - the definition of what this project does not do. Closest alternative: the timeline band, its separators and an accent line for the selected track.
§14-15 Dropdown and context menus as glass cardsThose popups belong to Premiere's process and are themed by Windows. No supported external theming exists. They stay exactly as they are.
§13 Buttons, §19 sliders/checkboxes/keyframes, §18 search field, §21 toolbar iconsPremiere's own drawing, with no HWND behind them. Alternative: region chrome around them (separators, bands, accents), which is what class C delivers.
§9-10 Background blur behind panelsWindows can blur only a process's own window. Blurring Premiere's pixels requires constant screen capture and reprojection - explicitly ruled out. Alternative: static gradients that read as depth.
§11 Panel hover/active/focus states on Premiere's panelsPremiere's panels never tell an outside process that the pointer is over them. Alternative: focus-aware treatment of the tracked window as a whole (active window vs. inactive), which is measurable.
